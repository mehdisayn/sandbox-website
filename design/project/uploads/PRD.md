## 1. Overview & goal

**SANDBOX Web** is a website that runs AI-generated JSX and HTML artifacts in the browser. It is the web counterpart of the existing SANDBOX Android app — same product, same screens, same idea — rebuilt as a hosted web app.

A user brings a `.jsx` or `.html` file (typically generated by an AI tool like Claude) into SANDBOX by dropping it in, pasting it, picking it, or importing it from a URL. Each artifact becomes a named, icon-tagged "mini-app" in a persistent **Library**. Opening it runs the artifact in a sandboxed runtime preloaded with React + Babel + Tailwind.

**Tagline:** *Run AI artifacts in your browser.*

### Goal

Give a power user of AI tools a personal, always-available library of runnable artifacts — reachable from any browser, with no app install — while preserving the local-only, no-accounts simplicity of the original.

### Problem

AI tools generate JSX/HTML artifacts constantly, but they only run inside the AI tool's own interface. There's no way to keep a personal library of them, open them as standalone mini-apps, or come back to a useful one later. SANDBOX Web solves this with a hosted runtime that treats each artifact as a first-class app.

## 2. Scope for v1

**In scope:**
- A hosted website (static site, no backend).
- Local-only storage in the browser (IndexedDB) — single user, single browser.
- Running `.jsx` and `.html` artifacts in a sandboxed runtime with React + ReactDOM + Babel + Tailwind preloaded.
- On-demand dependency fetching from a CDN whitelist, cached locally.
- The full set of screens carried over from the native app (see §3).
- Ingestion by drag-drop, paste, file picker, and URL import.

**Requires internet for:** loading the site itself and fetching not-yet-cached dependencies. It does **not** require a backend.

**Deferred (see §6 Non-goals):** accounts, sync, shareable links, PWA/offline.

### Target user

Primary user (v1): the owner. A frequent user of AI tools who generates UI artifacts often and wants a personal library of them, reachable from any browser. Comfortable with the concept of a `.jsx` file but not interested in a heavyweight dev setup.

## 3. Screen-by-screen requirements

All screens in light + dark mode. The provided design is the visual contract.

### 3.1 Library (`/`)
- Grid and list views of saved artifacts, with a toggle.
- Each artifact shows its icon (emoji / glyph / image) and name.
- Search bar filters by name.
- "Add mini-app" entry point offering: pick a file, paste code, import from URL (and drag-drop is always live on this screen).
- Per-artifact context menu (right-click / long-press): Open, Details, Edit code, Rename, Change icon, Share, Delete.
- Empty state: a friendly first-run prompt with a single "add your first artifact" call to action.

### 3.2 Run (`/run/:id`)
- Full-bleed artifact runtime with a thin top bar (icon + name on the left, a close/back control on the right).
- The artifact runs in a sandboxed iframe.
- Loading state while the runtime boots; error state if the artifact throws.
- If the artifact makes a network call that fails, show a non-blocking offline banner.

### 3.3 Details (`/details/:id`)
- Artifact metadata: icon, name, date added, file size, file kind, dependencies used.
- Actions: Rename, Change icon, Share, Delete.

### 3.4 Compose (`/compose`)
- A text editor to create a new artifact from scratch, or edit an artifact's source.
- Kind toggle (`jsx` / `html`), name field, icon picker.
- On save, imports are detected and dependencies fetched.

### 3.5 Share / Import (`/share`, modal)
- The "customize before saving" sheet for an incoming artifact (from file pick, drop, paste, or URL).
- Editable name; icon picker with emoji, glyph, and image-upload options.
- Shows detected file size and kind.
- "Add to Library" commits it; triggers dependency detection.

### 3.6 Settings (`/settings`)
- Hub linking to: Appearance, Featured mini-apps, Dependencies, Storage, Logs, About, Credits.
- A "network allowed" toggle (gates dependency fetching).
- A "reset library" destructive action.

### 3.7 Settings sub-screens
- **Appearance** (`/settings/appearance`) — theme selector: System / Light / Dark.
- **Dependencies** (`/settings/dependencies`) — list of cached dependency bundles with size and usage count; delete with a destructive confirm that names the affected artifacts.
- **Storage** (`/settings/storage`) — usage breakdown (artifacts vs dependencies) with totals; backed by `navigator.storage.estimate()`.
- **Logs** (`/settings/logs`) — captured console output from artifact runs, with level, timestamp, search, and clear.
- **Featured** (`/settings/featured`) — the built-in starter mini-apps, each with an "add" action.
- **About** (`/settings/about`) — version, tagline, platform note.
- **Credits** (`/settings/credits`) — open-source attribution and builder links.

## 4. Ingestion requirements

All four paths converge on one internal entry point — `{ content, filename, kind }` — and then open the Share/Import modal (§3.5).

| Path | Requirement |
|---|---|
| **File picker** | `<input type="file">` accepting `.jsx`, `.html`, `.htm`, `.js`, `.txt`. Reads file text. |
| **Drag-and-drop** | A dropzone (at minimum the Library screen) accepting dropped files or dropped text. |
| **Paste** | Paste artifact source directly (e.g. into Compose or a paste field). |
| **URL import** | Paste a raw `.jsx`/`.html` URL; the app fetches it (subject to CORS — a proxy may be needed for some hosts, deferred). |

File kind (`jsx` vs `html`) is inferred from the filename extension, with `jsx` as the default — see the `inferKind` / `inferName` helpers in `app/src/lib/artifacts.ts`.

## 5. Data model

Local-only, stored in IndexedDB via Dexie. The relational shape is kept identical to the native app's SQLite schema (and to the future server schema) so an accounts/sync migration later is a data copy, not a reshape.

| Store | Fields |
|---|---|
| **artifacts** | `id` (UUID), `name`, `iconType` (`emoji`\|`glyph`\|`image`), `iconValue`, `iconFill`, `fileKind` (`jsx`\|`html`), `source` (string — the artifact code, stored inline), `sizeBytes`, `createdAt`, `lastOpened` |
| **dependencies** | `id` (UUID), `name` (import specifier), `version`, `source` (string — the UMD/IIFE JS), `sizeBytes`, `downloadedAt` |
| **artifactDeps** | `artifactId`, `dependencyId` — join table (composite key) |
| **prefs** | `key`, `value` — settings (theme, network-allowed, etc.) |
| **icons** | `id`, `blob` — uploaded image icons |

Notable differences from the native model: there is no `file_path` (source is stored inline, not as a file), and the artifact source lives in the `artifacts` store rather than on a file system.

## 6. Non-goals (v1)

- **Accounts, sync, cloud storage** — deferred; the data layer is built to allow it later (see [`ARCHITECTURE.md`](./ARCHITECTURE.md) §6).
- **Shareable links** — depends on a backend; deferred with accounts.
- **PWA / offline / installability** — not in v1; a candidate for the polish phase.
- **PWA Web Share Target** — explicitly out; ingestion is drag-drop / paste / file / URL only.
- **Native mobile apps** — the existing Android app continues to exist separately; this is the web product.
- **Code editing of existing artifacts beyond Compose** — Compose can create and edit source; no separate in-place editor.
- **Multi-file artifacts or asset bundles** — single-file artifacts only.
- **Languages beyond JSX/TSX/HTML** — no Vue, Svelte, Python, etc.
- **Telemetry, analytics, monetization.**

---

## 7. Success criteria

For v1, SANDBOX Web is "done" when:

1. I can get a `.jsx` artifact into the Library by dropping it, pasting it, picking it, or importing it from a URL — with the name and icon I chose.
2. I can open it and it runs in the sandboxed runtime.
3. An artifact that imports an npm package works — the dependency is fetched once, cached, and reused.
4. The artifact code cannot read my Library, settings, or anything else outside its sandbox (the security model holds).
5. I can rename, re-icon, and delete artifacts without errors.
6. Everything above works from any modern browser with no install and no account.
